## Basic Usage

```typescript
import { App, Tool, ToolContext } from '@frontmcp/sdk';
import { z } from '@frontmcp/sdk';

@Tool({
  name: 'get_user',
  inputSchema: { userId: z.string() },
})
class GetUserTool extends ToolContext {
  async execute(input: { userId: string }) {
    return { id: input.userId, name: 'John' };
  }
}

@App({
  name: 'users',
  description: 'User management application',
  tools: [GetUserTool],
})
export class UsersApp {}
```

## Signature

```typescript
function App(providedMetadata: LocalAppMetadata): ClassDecorator
```

## Configuration Options

### Required Properties

| Property | Type     | Description             |
| -------- | -------- | ----------------------- |
| `name`   | `string` | Unique application name |

### Optional Properties

| Property      | Type                           | Description                                                                                                                                                                                                                                                                                                           |
| ------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | `string`                       | Stable identifier for tracking                                                                                                                                                                                                                                                                                        |
| `description` | `string`                       | Human-readable description                                                                                                                                                                                                                                                                                            |
| `auth`        | `AuthOptionsInput`             | App-level auth. On its own endpoint (`standalone: true`, `splitByApp`) it is the endpoint's auth; on the shared endpoint a `public` or `static` server refuses to start with a protected app, and a `local` or `remote` server checks each tool call against the caller's authorized apps only with `incrementalAuth` |
| `standalone`  | `boolean \| 'includeInParent'` | If `true`, the app gets its own scope. If `'includeInParent'`, it acts as a separated scope under the app-name prefix.                                                                                                                                                                                                |
| `output`      | `OutputPolicy`                 | App-level output-validation + output-schema exposure policy (`allowNonFinite`, `schemaMode`, `schemaDescriptionFormat`). Overrides the server policy; overridable per `@Tool` (Tool > App > server). See [Output schema exposure](/frontmcp/servers/tools#output-schema-exposure)                                     |
| `ui`          | `{ servingMode? }`             | Tool UI defaults for this app's tools: `servingMode` applies to each tool whose `ui` sets none (Tool > App > server `@FrontMcp({ ui })` > `'auto'`). Same values as a tool's `ui.servingMode`. See [Tool UI](/frontmcp/servers/tools#tool-ui)                                                                         |

### Components

| Property    | Type             | Description                        |
| ----------- | ---------------- | ---------------------------------- |
| `tools`     | `ToolType[]`     | Tools defined by this app          |
| `resources` | `ResourceType[]` | Resources defined by this app      |
| `prompts`   | `PromptType[]`   | Prompts defined by this app        |
| `agents`    | `AgentType[]`    | Agents defined by this app         |
| `skills`    | `SkillType[]`    | Skills defined by this app         |
| `jobs`      | `JobType[]`      | Jobs registered by this app        |
| `workflows` | `WorkflowType[]` | Workflows registered by this app   |
| `channels`  | `ChannelType[]`  | Notification channels for this app |

```typescript
@App({
  name: 'crm',
  tools: [GetContactTool, CreateContactTool],
  resources: [ContactResource],
  prompts: [SalesEmailPrompt],
  agents: [SalesAgent],
  skills: [LeadQualificationSkill],
})
class CrmApp {}
```

### Extension Points

| Property        | Type                 | Description                     |
| --------------- | -------------------- | ------------------------------- |
| `providers`     | `ProviderType[]`     | App-scoped dependency providers |
| `plugins`       | `PluginType[]`       | App-specific plugins            |
| `authProviders` | `AuthProviderType[]` | Authentication providers        |
| `adapters`      | `AdapterType[]`      | Framework adapters              |

```typescript
@App({
  name: 'crm',
  providers: [CrmService, ContactRepository],
  plugins: [AuditPlugin],
  authProviders: [SalesforceOAuthProvider],
})
class CrmApp {}
```

### Configuration via Providers

`@App` does not accept a free-form `config` field. Bind the configuration to a token with a factory provider, and read it with `this.get(CRM_CONFIG)`:

```typescript
import { App, type Token } from '@frontmcp/sdk';

interface CrmConfig {
  apiBaseUrl: string;
  maxRetries: number;
}

export const CRM_CONFIG: Token<CrmConfig> = Symbol('CrmConfig');

@App({
  name: 'crm',
  providers: [
    {
      name: 'CrmConfig',
      provide: CRM_CONFIG,
      useFactory: (): CrmConfig => ({ apiBaseUrl: 'https://api.salesforce.com', maxRetries: 3 }),
    },
  ],
})
class CrmApp {}
```

`providers` accepts `@Provider` classes, factory providers (`{ name, provide, inject?, useFactory }`), and named `{ name, provide, useValue }` and `{ name, provide, useClass }` objects; see [@Provider](/frontmcp/sdk-reference/decorators/provider#factory-providers).

## Multi-App Architecture

FrontMCP supports organizing functionality across multiple apps:

```typescript
import { FrontMcp, App, Tool, ToolContext } from '@frontmcp/sdk';

// User management app
@App({
  name: 'users',
  tools: [GetUserTool, CreateUserTool, UpdateUserTool],
  resources: [UserProfileResource],
})
class UsersApp {}

// Order management app
@App({
  name: 'orders',
  tools: [GetOrderTool, CreateOrderTool],
  resources: [OrderResource, OrderHistoryResource],
})
class OrdersApp {}

// Analytics app
@App({
  name: 'analytics',
  tools: [GetMetricsTool, GenerateReportTool],
  agents: [AnalyticsAgent],
})
class AnalyticsApp {}

// Main server combining all apps
@FrontMcp({
  info: { name: 'E-Commerce Platform', version: '1.0.0' },
  apps: [UsersApp, OrdersApp, AnalyticsApp],
})
export default class ECommercePlatform {}
```

## App Isolation

Each app maintains its own:

- Tool namespace (tools are prefixed with `<app id>:` on a name conflict)
- Provider scope (providers are isolated per app)
- Auth context (apps can have different auth providers)

```typescript
// Tools from different apps can have the same name
@App({
  name: 'github',
  tools: [SearchTool], // Listed as 'github:search' on a conflict
})
class GitHubApp {}

@App({
  name: 'jira',
  tools: [SearchTool], // Listed as 'jira:search' on a conflict
})
class JiraApp {}
```

## Provider Inheritance

Apps can access providers from the parent server:

```typescript
// In a tool
@Tool({ name: 'my_tool', inputSchema: {} })
class MyTool extends ToolContext {
  async execute() {
    // Access server-level provider
    const config = this.get(ConfigService);
    // Access app-level provider
    const service = this.get(MyAppService);
    return { ok: true };
  }
}

@App({
  name: 'my-app',
  providers: [MyAppService], // App-specific provider
  tools: [MyTool],
})
class MyApp {}

@FrontMcp({
  info: { name: 'My Server', version: '1.0.0' },
  apps: [MyApp],
  providers: [ConfigService], // Available to all apps
})
class Server {}
```

Declare each class before a decorator lists it: decorator arguments are evaluated when the decorated class is defined, so `apps: [MyApp]` cannot refer to a `class MyApp` declared further down.

## Standalone vs Gateway Apps

### Standalone App

A standalone app runs independently:

```typescript
@App({
  name: 'standalone-app',
  standalone: true,
  tools: [MyTool],
})
class StandaloneApp {}

@FrontMcp({
  info: { name: 'Server', version: '1.0.0' },
  apps: [StandaloneApp],
  splitByApp: true, // Each standalone app gets its own scope
})
class Server {}
```

### Gateway App

Apps without `standalone: true` are combined in a gateway scope:

```typescript
@App({ name: 'app1', tools: [Tool1] })
class App1 {}

@App({ name: 'app2', tools: [Tool2] })
class App2 {}

@FrontMcp({
  info: { name: 'Gateway', version: '1.0.0' },
  apps: [App1, App2], // Combined into single gateway scope
})
class Gateway {}
```
