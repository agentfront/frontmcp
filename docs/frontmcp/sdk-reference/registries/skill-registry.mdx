## Overview

`scope.skills` is typed `SkillRegistryInterface`. `getInlineSkills()`, `adoptFromChild()` and `setExternalProvider()` are on the exported `SkillRegistry` class only: narrow with `instanceof SkillRegistry` to call them.

```typescript
import { SkillRegistry } from '@frontmcp/sdk';

// Access via scope
const skills = scope.skills;

// List all skills
const allSkills = skills.getSkills();

// Search skills
const results = await skills.search('data analysis');

// Load a skill
const skill = await skills.loadSkill('data-pipeline');
```

## Methods

### getSkills()

Get all skills with optional filtering.

```typescript
getSkills(options?: boolean | GetSkillsOptions): SkillEntry[]
```

A boolean is `includeHidden`.

| Option          | Type                       | Description                                                                                                |
| --------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `includeHidden` | `boolean`                  | Include hidden skills                                                                                      |
| `visibility`    | `'mcp' \| 'http' \| 'all'` | Filter by visibility: `'mcp'` or `'http'` keeps that one and `'both'`; `'all'` (default) keeps every skill |

**Example:**

```typescript
// Get all visible skills
const skills = registry.getSkills();

// Get skills visible via HTTP
const httpSkills = registry.getSkills({ visibility: 'http' });
```

### search()

Search skills using TF-IDF text matching.

```typescript
search(query: string, options?: SkillSearchOptions): Promise<SkillSearchResult[]>
```

| Option            | Type       | Description                                          |
| ----------------- | ---------- | ---------------------------------------------------- |
| `topK`            | `number`   | Maximum results to return                            |
| `minScore`        | `number`   | Minimum similarity score (0-1)                       |
| `tags`            | `string[]` | Only skills with these tags                          |
| `tools`           | `string[]` | Only skills that reference these tools               |
| `requireAllTools` | `boolean`  | Only skills whose referenced tools are all available |
| `excludeIds`      | `string[]` | Skill ids to leave out                               |

Each `SkillSearchResult` has the skill's `metadata`, its `score`, its `availableTools` and `missingTools`, and its `source` (`'local'` or `'external'`).

**Example:**

```typescript
const results = await registry.search('data analysis', {
  topK: 10,
  minScore: 0.5,
});

for (const result of results) {
  console.log(`${result.metadata.name}: ${result.score}`);
}
```

### loadSkill()

Load skill content by ID/name with tool validation.

```typescript
loadSkill(skillId: string): Promise<SkillLoadResult | undefined>
```

Resolves `undefined` when no skill has that id or name.

**Example:**

```typescript
const loaded = await registry.loadSkill('data-pipeline');
if (loaded) {
  console.log(loaded.skill.instructions); // Full skill content
  console.log(loaded.availableTools);     // Referenced tools that are registered
  console.log(loaded.missingTools);       // Referenced tools that are not
}
```

### listSkills()

List skills with pagination support.

```typescript
listSkills(options?: SkillListOptions): Promise<SkillListResult>
```

| Option          | Type                                  | Description                 |
| --------------- | ------------------------------------- | --------------------------- |
| `offset`        | `number`                              | Starting index              |
| `limit`         | `number`                              | Maximum results             |
| `tags`          | `string[]`                            | Only skills with these tags |
| `sortBy`        | `'name' \| 'priority' \| 'createdAt'` | Sort field                  |
| `sortOrder`     | `'asc' \| 'desc'`                     | Sort direction              |
| `includeHidden` | `boolean`                             | Include hidden skills       |

`SkillListResult` has the page's `skills` (their metadata), the `total` count and `hasMore`.

**Example:**

```typescript
const page = await registry.listSkills({
  offset: 0,
  limit: 20,
});

console.log(`Total: ${page.total}`);
console.log(`Skills: ${page.skills.length}`);
```

### validateAllTools()

Validate all skills' tool references against the ToolRegistry.

```typescript
validateAllTools(): Promise<SkillValidationReport>
```

**Example:**

```typescript
import { SkillValidationError, type SkillValidationReport } from '@frontmcp/sdk';

let report: SkillValidationReport;
try {
  report = await registry.validateAllTools();
} catch (error) {
  // A 'strict' skill that references a missing tool throws, unless failOnInvalidSkills is false
  if (!(error instanceof SkillValidationError)) throw error;
  report = error.report;
}

for (const result of report.results) {
  if (result.status === 'failed') {
    console.error(`${result.skillName}: missing tools ${result.missingTools.join(', ')}`);
  }
}
```

### adoptFromChild()

Adopt skills from a child registry. On the `SkillRegistry` class only.

```typescript
adoptFromChild(child: SkillRegistry, _childOwner: EntryOwnerRef): Promise<void>
```

When a child's skill is removed, the adopting registry stops serving it at once, including from its storage provider.

### registerSkillContent()

Register a skill at runtime from a fully resolved `SkillContent`. Registering again with the same `id` replaces the skill.

```typescript
registerSkillContent(content: SkillContent, opts?: RegisterSkillContentOptions): Promise<RegisteredSkillContent>
```

| Option       | Type                | Description                                                                                                                                     |
| ------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`     | `string`            | Where the skill came from, for logs                                                                                                             |
| `supersedes` | `readonly string[]` | Ids of skills registered this way that the same change replaces or removes. The id/path collision check treats them as already gone (see below) |

`RegisteredSkillContent`:

| Field        | Type                  | Description                                                                                  |
| ------------ | --------------------- | -------------------------------------------------------------------------------------------- |
| `id`         | `string`              | The registered skill's id                                                                    |
| `unregister` | `() => Promise<void>` | Removes this registration; a no-op once a later registration of the same id replaced it      |
| `removed`    | `readonly string[]`   | Ids of superseded skills this registration removed, because the new skill collided with them |

A skill whose `id` is another skill's `skill://` path, or whose path is another skill's `id`, is refused with `INVALID_PARAMS` and nothing changes, since `skill://<id>/SKILL.md` would serve one for the other. The check covers every registry that serves this one's skills: the registries that adopt it, and their other children.

A change that registers its new skills before removing the old ones, such as a skill bundle sync, names the old ones in `supersedes`, so a new skill can take the name of one it drops or renames. A superseded skill the new one collides with is removed in the same step, so the two are never served together, and is listed in `removed`. The other superseded skills stay registered until the caller registers them again or unregisters them.

**Example:**

```typescript
const handle = await scope.skills.registerSkillContent(
  { id: 'reports', name: 'reports', description: 'Quarterly reports', instructions: '# Reports', tools: [] },
  { source: 'my-plugin', supersedes: ['reports-v1'] },
);
console.log(handle.removed); // ['reports-v1'] when that skill held the path `reports`
await handle.unregister();
```

### unregisterSkill()

Remove a skill registered with `registerSkillContent()`. Returns `false` when no such skill is registered.

```typescript
unregisterSkill(id: string): Promise<boolean>
```

The skill leaves the registry at once. If the storage provider fails to remove its copy, the registry still stops serving it from `search()`, `listSkills()`, `count()` and `loadSkill()`.

## External Storage

Skills can be synced to external storage for persistence:

### setExternalProvider()

Configure an external storage provider. On the `SkillRegistry` class only. In `'read-only'` mode the registry searches, lists and loads skills through the provider; in `'persistent'` mode it keeps its own storage, and `syncToExternal()` writes the local skills to the provider.

```typescript
setExternalProvider(provider: ExternalSkillProviderBase): void
```

**Example:**

```typescript
import { ExternalSkillProviderBase, SkillRegistry, type SkillContent } from '@frontmcp/sdk';

class RestSkillProvider extends ExternalSkillProviderBase {
  protected async fetchSkill(skillId: string): Promise<SkillContent | null> {
    const response = await fetch(`https://skills.example.com/skills/${skillId}`);
    return response.ok ? response.json() : null;
  }

  // ...fetchSkills, searchExternal, upsertSkill, deleteSkill, countExternal and existsExternal
}

// Inside a tool, resource or prompt
if (this.scope.skills instanceof SkillRegistry) {
  this.scope.skills.setExternalProvider(new RestSkillProvider({ mode: 'read-only' }));
}
```

`@frontmcp/sdk` exports `ExternalSkillProviderBase` together with the types its constructor and abstract methods take: `ExternalSkillMode`, `ExternalSkillProviderOptions`, `ExternalSkillSearchOptions`, `ExternalSkillListOptions` and, for `options.syncStateStore`, `SkillSyncStateStore`, `SkillSyncState`, `SkillSyncEntry` and `SkillSyncStatus`. Up to 1.9.0 it did not export them, so a provider could not be written outside the SDK.

### syncToExternal()

Sync local skills to external storage. Resolves `null` when no external provider is configured.

```typescript
syncToExternal(): Promise<SyncResult | null>
```

**Example:**

```typescript
// Sync skills
const result = await registry.syncToExternal();
if (result) {
  console.log(`Added ${result.added.length}, updated ${result.updated.length}, removed ${result.removed.length}`);
}
```

### hasExternalProvider()

Check if external provider is configured.

```typescript
hasExternalProvider(): boolean
```

### getExternalProvider()

Get the configured external provider.

```typescript
getExternalProvider(): ExternalSkillProviderBase | undefined
```

## SkillEntry Accessors

Each skill in the registry is a `SkillEntry` with these accessor methods:

| Method               | Return Type                           | Description                                 |
| -------------------- | ------------------------------------- | ------------------------------------------- |
| `getDescription()`   | `string`                              | Skill description                           |
| `getToolRefs()`      | `SkillToolRef[]`                      | Normalized tool references                  |
| `getToolNames()`     | `string[]`                            | Tool name strings                           |
| `getTags()`          | `string[]`                            | Categorization tags                         |
| `getPriority()`      | `number`                              | Search ranking priority                     |
| `isHidden()`         | `boolean`                             | Whether hidden from discovery               |
| `getLicense()`       | `string \| undefined`                 | License (per Agent Skills spec)             |
| `getCompatibility()` | `string \| undefined`                 | Compatibility notes (per Agent Skills spec) |
| `getSpecMetadata()`  | `Record<string, string> \| undefined` | Arbitrary metadata (per Agent Skills spec)  |
| `getAllowedTools()`  | `string \| undefined`                 | Pre-approved tools (per Agent Skills spec)  |
| `getResources()`     | `SkillResources \| undefined`         | Bundled resource directories                |

```typescript
const skill = registry.findByName('review-pr');
if (skill) {
  console.log(skill.getLicense());       // 'MIT'
  console.log(skill.getCompatibility()); // 'Requires git CLI'
  console.log(skill.getResources());     // { scripts: '...', references: '...' }
}
```

## Skill Visibility

Skills can have different visibility modes:

| Visibility | Description                     |
| ---------- | ------------------------------- |
| `mcp`      | Available only via MCP protocol |
| `http`     | Available only via HTTP API     |
| `both`     | Available via both MCP and HTTP |

```typescript
@Skill({
  name: 'internal-task',
  description: 'Internal maintenance steps',
  instructions: '# Internal task',
  visibility: 'mcp', // Only for MCP clients
})
class InternalTask extends SkillContext { }

@Skill({
  name: 'public-api',
  description: 'How to call the public API',
  instructions: '# Public API',
  visibility: 'http', // Only for HTTP clients
})
class PublicAPI extends SkillContext { }
```

## Tool Validation

Skills can reference tools that must exist in the registry:

```typescript
@Skill({
  name: 'data-pipeline',
  description: 'Fetch, transform and save data',
  instructions: '# Data pipeline',
  tools: ['fetch_data', 'transform', 'save_results'],
  toolValidation: 'strict',
})
class DataPipeline extends SkillContext { }
```

Validation modes (`toolValidation`):

- **strict**: The server refuses to start if a referenced tool is not registered (`validateAllTools()` throws `SkillValidationError`, unless the registry was created with `failOnInvalidSkills: false`; `@FrontMcp({ skillsConfig: { failOnInvalidSkills: false } })` creates the server's that way)
- **warn**: Log warning for missing tools (default)
- **ignore**: Skip validation
