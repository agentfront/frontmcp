# MCP Events conformance (SEP-3415)

This matrix maps every requirement of the MCP Events conformance suite to how FrontMCP meets it. The suite is
[modelcontextprotocol/conformance#521](https://github.com/modelcontextprotocol/conformance/pull/521), not merged yet,
read at head commit `76fef32dad810143a56819065b286fa0e93a7256`. Its requirement file lists 133 graded rows, which carry
ids, and 40 excluded rows, which do not; the excluded rows are numbered here `excluded-01` to `excluded-40` in the order
the file lists them.

The suite itself is not run here. Each row is checked by our own tests, against `src/main.conformance.ts`: the events
of this app, plus test-only events and controls (`src/apps/conformance`) that make conditions a healthy server never
has, such as a failing or gapped upstream and revoked access. Tests that need several principals mint a token for each.

## Known deviations

- **`sep-3415-unsubscribe-unknown-not-found`.** `events/unsubscribe` answers `{}` whether or not a subscription
  existed. The OpenAI design asks for an idempotent unsubscribe, and a client that retries a cleanup should not see an
  error the second time. SEP-3415 asks for `NotFound` (-32023).
- **`sep-3415-result-type-complete`**, on an `initialize` session only. `resultType` is a 2026-07-28 convention;
  results over an `initialize` session do not carry it. Every 2026-07-28 result does.
- **`sep-3415-poll-one-subscription-per-request`** and **`sep-3415-subscribe-secret-required`**, on an `initialize`
  session only. A request that fails the method's request schema (no `name`, no `delivery.secret`) is answered -32603
  by the MCP SDK protocol layer, as it is for every method. Under 2026-07-28 both are answered -32602.

## Dialects

A client detected as OpenAI (ChatGPT) is answered in the dialect of the OpenAI design: the error codes -32011 to
-32015 instead of -32023 to -32027, and the `eventId` as the `webhook-id` of a delivery. Every other client gets
SEP-3415. `events.compat` pins one dialect for every client. The rows above are graded for SEP-3415 clients; the
OpenAI dialect is covered by P "answers a client detected as OpenAI with the codes of the design sketch", existing
events-subscriptions "answers a client detected as OpenAI with the codes of the design sketch" and existing
events-delivery "uses the event id as webhook-id for a subscription a client detected as OpenAI created".

## What the suite checks wrongly

Read from the suite at the commit above. These are worth raising on the pull request.

- `events-webhook` subscribes to `https://conformance.invalid/...`, which never resolves. A server that verifies the
  callback before it accepts the subscription, as SEP-3415 requires before any delivery, refuses it with -32027, and
  every row of the scenario then reports untestable.
- The raw requests (the `Mcp-Name` probes, `events/stream`, `subscriptions/listen`) carry no `Authorization` header
  and no session id, so a server that signs callers in answers 401 and fails for a reason unrelated to the row.
- `sep-3415-result-type-complete` is graded over an `initialize` session too, where `resultType` does not apply.
- `sep-3415-stream-cancel-stops-delivery` always passes: aborting the request also stops the harness reading.
- `sep-3415-stream-gap-resends-active` wants `truncated: true` after a gap where `sep-3415-truncated-false-when-no-replay`
  wants `false`, on the same kind of event without replay. The latter also counts only an explicit `cursor: null`,
  though an absent cursor means the same.
- The poll occurrence loop keeps sending `cursor: null` for an event without replay, so it only sees events if a
  server breaks "`cursor: null` starts from now", which `sep-3415-cursor-null-starts-from-now` grades.
- `sep-3415-ssrf-reject-non-routable` and `sep-3415-ssrf-validate-callback-url` grade a SHOULD as FAILURE and ignore
  the "unless explicitly configured" exception.
- `sep-3415-delivery-retries-bounded` cannot fail: the receiver accepts the third attempt. The retry check compares
  only `webhook-timestamp`, which has one-second resolution.
- `sep-3415-capability-list-changed-gated` passes `eventsListChanged: false`, though the server must omit it, and
  `sep-3415-mcp-name-list-exempt` reads any 400 as a refusal of the missing header.
- An empty catalog, legal in SEP-3415, grades the descriptor rows red, and `sep-3415-error-not-found` probes
  `events/poll` even when no event offers poll.
- `sep-3415-replay-ceiling-sets-truncated` is a MUST graded as WARNING, and `sep-3415-poll-one-subscription-per-request`
  expects -32602 where the spec names no code.
- The removal rows need a catalog that changes at runtime, through an `events_conformance_catalog` control whose
  `retype` and `extend` operations are not documented; a server with a fixed catalog reports them untestable at
  FAILURE.
- `sep-3415-server-identity-key-discovery` is a rule for the client, which no server scenario can observe.
