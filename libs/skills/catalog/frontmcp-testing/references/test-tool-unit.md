# Unit Testing a Tool

```typescript
import { z } from '@frontmcp/sdk';

import { AddTool } from '../tools/add.tool';

// `new AddTool()` throws: build the tool from its prototype and mock the context methods it calls.
function createAddTool(): AddTool {
  const tool: AddTool = Object.create(AddTool.prototype);
  Object.assign(tool, {
    get: jest.fn(),
    tryGet: jest.fn(),
    fail: jest.fn((error: Error) => {
      throw error;
    }),
    mark: jest.fn(),
    fetch: jest.fn(),
    notify: jest.fn(),
  });
  return tool;
}

describe('AddTool', () => {
  it('should add two numbers', async () => {
    const tool = createAddTool();
    const result = await tool.execute({ a: 2, b: 3 });
    expect(result).toEqual({ sum: 5 });
  });

  it('should handle negative numbers', async () => {
    const tool = createAddTool();
    const result = await tool.execute({ a: -1, b: -2 });
    expect(result).toEqual({ sum: -3 });
  });

  it('should throw on invalid input', async () => {
    // Zod validates before execute — test the schema separately
    const schema = z.object({ a: z.number(), b: z.number() });
    expect(() => schema.parse({ a: 'not-a-number' })).toThrow();
  });
});
```

## Creating the Tool Instance

`@Tool` returns the class unchanged, and the `ToolContext` constructor takes the arguments the server builds for each call (metadata, input, providers, logger, auth info). `new AddTool()` therefore fails to compile and throws a `TypeError` at runtime. `Object.create(AddTool.prototype)` creates the instance without running the constructor, which is also what the spec generated by `nx g @frontmcp/nx:app` does. The same works for `ResourceContext` and `PromptContext` subclasses.

Because the constructor does not run, the instance has none of the context's state:

- Assign the context methods the tool calls (`get`, `tryGet`, `fail`, `mark`, `fetch`, `notify`, `progress`) with `Object.assign`. Mock `fail` to rethrow its error: the real `fail` throws a flow-control signal that carries neither the error's class nor its message.
- Define the getters the tool reads, such as `auth` or `scope`, with `Object.defineProperty(tool, 'auth', { value: ... })`. They have no setter, so `Object.assign` throws a `TypeError` on them.
- To run the tool with its real context (input validation, providers, `this.auth`, hooks), call it through a server instead: see `test-direct-client`.
